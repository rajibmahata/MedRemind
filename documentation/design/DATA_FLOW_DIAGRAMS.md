## ?? Prescription Upload & Processing Flow

### Complete End-to-End Flow

```mermaid
sequenceDiagram
    participant U as User (Mobile)
    participant M as Mobile App
    participant A as Backend API
    participant F as File Storage
    participant O as Azure OCR
    participant P as Python Middleware
    participant L as LLMs
    participant D as Database
    
    U->>M: 1. Capture/Select Image
    M->>M: 2. Compress Image
    
    M->>A: 3. POST /api/prescriptions/upload
    Note over M,A: JWT Token + Image (Base64)
    
    A->>F: 4. Save Image File
    F-->>A: File Path + Size
    
    A->>D: 5. Create Prescription Record
    Note over A,D: Status: Processing
    
    A->>O: 6. Extract OCR Text
    O-->>A: OCR Text
    
    A->>D: 7. Check for Duplicate
    Note over A,D: SHA256 Hash Comparison
    
    alt Is Duplicate (>90% match)
        D-->>A: Existing Result
        A-->>M: Return Cached Data ?
    else Not Duplicate
        A->>P: 8. Send to Python Middleware
        Note over A,P: OCR Text + Prescription ID
        
        P->>P: 9. CrewAI Agent 1: Normalize OCR
        
        P->>L: 10. CrewAI Agent 2: Extract Data
        Note over P,L: Try OpenAI ? DeepSeek ? Claude
        L-->>P: Extracted Data (Patient, Doctor, Meds)
        
        P->>L: 11. CrewAI Agent 3: Validate Safety
        L-->>P: Safety Warnings + Interactions
        
        P-->>A: 12. Complete Result
        Note over P,A: Medications + Validation + Metadata
        
        A->>D: 13. Store OCR Result
        Note over A,D: PrescriptionOCRResult table
        
        A->>D: 14. Update Prescription Status
        Note over A,D: Status: Processed
        
        A-->>M: 15. Return Result
    end
    
    M->>M: 16. Display Medications
    M-->>U: 17. Show Results + Warnings
```

## ?? Alternative Flows

### Flow 1: Duplicate Prescription Detected

```
User uploads ? File saved ? OCR extracted ? 
Duplicate found (>90% match) ? 
Return existing result immediately ?
(Saves ~10s + LLM API costs!)
```

### Flow 2: LLM Fallback Scenario

```
OCR text ? Python Middleware ?
OpenAI fails ? Try DeepSeek ?
DeepSeek fails ? Try Claude ?
Claude succeeds ? Continue processing
```

### Flow 3: Processing Failure

```
User uploads ? File saved ? OCR fails ?
Update status to "Failed" ?
Return error message ?
User can retry
```

## ?? Key Flow Characteristics

### Performance Optimizations
1. ? **Image Compression** - Reduce upload time
2. ? **Duplicate Detection** - Skip processing if duplicate
3. ? **Parallel Processing** - LLM calls can be parallel
4. ? **Caching** - Cache OCR results
5. ?? **CDN Integration** - Serve static files (Future)

### Error Handling
1. ? **Graceful Degradation** - Try multiple LLMs
2. ? **Retry Logic** - Retry on transient failures
3. ? **Clear Error Messages** - User-friendly errors
4. ? **Logging** - Comprehensive debug logs
5. ? **Status Updates** - Prescription status tracking

### Data Integrity
1. ? **Transactions** - Unit of Work pattern
2. ? **Validation** - Input/output validation
3. ? **Constraints** - Database foreign keys
4. ? **Hash Verification** - OCR text hashing
5. ? **Audit Trail** - All LLM responses stored
